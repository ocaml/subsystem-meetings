#### Automatic generalization

We are trying to do generalization automatically instead of explicitly. In GHC this is easy to do, but here is it very difficult.

Originally I was thinking that we would take this chance of the way we use... It happens that we can create a type at generic level, and then lower it to anything else. It is supposed to be a type scheme, but we also use it "a (monomorphic) type whose level we don't care about". We use this in the pattern-matching compiler, the `solve_*` helpers around `type_pat`.

### Type error messages

Richard: we are trying to improve error messages. It started around layouts. We implemented this idea of layout histories, we track where it came from.

This was pretty good, but there were a few cases that were pretty hard. We made the design decision that when a type gets generalized, we would forget about its history. (If we have some general `f`, it is fully settled, we don't care about its internals anymore.) It seemed like generalization was the good place to do that.

Jacques: sometimes we use this dirty trick where we generalize (just to check that it is at young level) and then lower the level again, you may not want to forget histories in this case.

Gabriel: would it make sense with other types?

Richard: yes, but layouts are like a testbed for now, to work out the ideas, before we consider generalizing (no pun intended) further.
