My question: do we see this a possibility of using nominal types to control optimizations? If I have have an external `"int"`, I should know that it is not a float. If I have a mutable external `"int"`, I should know that I don't need `caml_modify`.

#### Compatibility

Gabriel: can we stop handling local abstract types specially? External types are partly designed to solve this.

Compatibility issues?

Conclusion:

- for types that are only used for GADT indices, define an explicit constructor (``type t = private A``)

- for types that are populated from the FFI there could be an issue, but we don't think this will occur in practice, because any distinction assumption will be broken


Gabriel: could we go ahead and remove the handling of local abstract types today, even without external types?

Jacques: no, because we need external types to deal with predefined types.
