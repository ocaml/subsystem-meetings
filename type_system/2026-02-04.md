### Alistair's complaints about `type t = external 'hi'` syntax 

A syntax like 
```
new type t 
```
allows us to extend the feature in future (if we want to)

The problem: parsing conflicts 
```ocaml
bar new baz
```

Would we be opposed to?
```ocaml
bar (new baz)
```

See https://github.com/ocaml/RFCs/pull/4 for a RFC doing that.

To summarize, changes to the parser would be backwards incompatible (bad!) 
and we could always introduce a similar syntax in future (alongside external)
