### Recursive signatures

https://github.com/ocaml/ocaml/pull/6818

```ocaml
(* proposal *)
module type rec R = sig
  val f : (module R) -> unit
end

(* current workaround *)
module rec R : sig
  module type T = sig
    val f: (module R.T) -> unit
  end
end = R
```

```ocaml
(* version from Gabriel *)
module rec R : sig
  module type T = sig
    val f: (module R.T) -> unit
  end
end = R

(* one-step unfolding of R.T *)
module type U = sig
  val f: (module R.T) -> unit
end

(* seems to work *)
let id (x : (module R.T)) = (x : (module U))
```


```ocaml
(* version from Nathanaëlle: two isomorphic cycles *)
module rec R : sig
  module type T = sig val f: (module R.T) -> unit end
  module type S = sig val f: (module R.S) -> unit end
end = R
(* Typechecker loops *)
module F(X : R.T) : R.S = X
```

Bug report: [#14743](https://github.com/ocaml/ocaml/issues/14743)

### Space leak in counter-example checking

https://github.com/ocaml/ocaml/pull/14727

Florian: we are using the same pool for checking all the counter-examples. If you have millions of them to check, you can end up using a lot of memory.

The fix that I have is just to create shadow pools for counter-example checking that are just discarded along the way. The other option would be to disable the pool.

Jacques: there is a subtle problem here, `simple_abbrev`, in non-principal mode we put the expansion of all the types that have no parameters in this one. We discard it once in a while, but I am a bit afraid that if you don't empty it, it may not be correct to discard the content of the pool.

Jacques: the alternative would be to use a generalizing one instead of the standard version. But indeed this is more work. So maybe just discard it.

General backtracking was removed here: https://github.com/ocaml/ocaml/pull/12932

Gabriel: so it sounds like Florian's approach is reasonable. I'm in favor of merging, but I do think we should consider backtracking more globally.



### Pipe type

New typing for `|>`: [#14286](https://github.com/ocaml/ocaml/pull/14286)

Jacques: do we want to change the semantics? I agree that we don't want to pay for using the pipe, but what is the correct semantics?

What's an example of semantics changes coming from optional arguments?

This typechecks
```ocaml
(Fun.id (fun ~x y -> x + y)) 0
```
(which is the current equivalent for `0 |> Fun.id (fun ~x y -> x + y)`)
this doesn't
```ocaml
Fun.id (fun ~x y -> x + y) 0
```
which is the new version.

Consensus: it would be okay to merge this PR.
