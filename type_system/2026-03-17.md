### optional argument elision

https://github.com/ocaml/ocaml/pull/14648

Florian: this code generates `fun x -> f ?labopt:None x` as a typedtree fragment. It does not sound realistic to support modular explicits as well, the typedtree fragment to generate would be humongous.

Florian: I propose to do at the `Lambda` level instead, by keeping a dedicated node in the type-checker.

The difficulty is to express the eta-expansion of a function which expects a modular explicit, especially when the input type carries constraints like `(M : S with type t = ...)`. We have the types, but generating the typed tree would be a lot of work.

Stefan: we also need to reimplement the well-founded check. I wrote the well-founded implementation, so Jacques will read that.

(Gabriel: I could review well-founded, but I'm more than happy to let Jacques do it.)

Jacques: I think we are ready now?

Jacques: I created a specific PR which is actually just doing the combination of the two on the OCaml repository, so that we can compare the result of the testsuite. There are a lot of differences, but they are mostly about, well. One kind of regression is that the strategy in keep-expansion, due to Path compression, we keep only one abbreviation. It may happen that this type abbreviation is invalidated. We might end up with no type abbreviation, and having to print the type in full. We approximate the notion of validity because we are doing the check in places where we don't have the full environment around; for example we say "if the type itself appears in one of its own arguments", then we don't use the abbreviation. I think in some cases currently it is going to print an abbreviation which does not really make sense.
