#### Regression

Samuel: when you are typing a recursive function you take an approximation of its type. Currently when you have a `type a. -> ...` at the beginning of the function type, you cannot approximate the rest. Same problem with modular explicits. When it's possible to have a modular explicit, we are not guessing the type of the function, it can be anything. In the function body you have less information about the type of the function, which means that in cases with first-class modules you can break a case where you needed the information to type a function.

Leo: in theory this is fixable.

Samuel: this occurs when there is a function that takes a first-class module, now we assume that it is dependent, but before we could assume that it was dependent.

Gabriel: do you have an example in the testsuite?

```ocaml
module type T = sig end
let rec f (module M : T) = f (module M)
```

The problem is that `(module M)` on the right-hand-side is not annotated, and to infer that we would need the approximation of `f` to know about the module parameter, and we don't know.

Leo: recursive functions are never usefully dependent.

Gabriel: but what if the return type is annotated?

Gabriel: it would be reasonable to say that if you partly annotate the rest of the type, the parts that are annotated may be dependent but the parts that are non-annotated are not dependent.

Gabriel: so my thinking is, where there are no annotations we could/should assume non-dependent.
